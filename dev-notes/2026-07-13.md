# 2026-07-13 开发记录

## 今日主题

落实第三次 DeepSeek 试玩复盘中的首批协议修复。目标不是继续扩展判定核心，而是修正 LLM 路径公平性、事件归因、叙事事实接地和自由输入接线。

## 形成的结论

### 空提议采用内容兜底

真实 trace 已经连续出现 10 个 `proposed_changes` 全为空，不能再只依赖 prompt 教导。若模型完全没有提出状态变化，CapabilityRouter 使用该意图在内容中声明的 `fallback_proposal`，并记录 `change.fallback_proposal_applied` adjustment。这样 LLM 路径不会弱于同意图菜单路径。

模型显式给出但被权限或白名单拒绝的提议不触发兜底，避免用默认效果掩盖错误计划。Prompt 同时弱化“拿不准就留空”的劝退措辞。

### Storylet 显式区分玩家回应与世界节拍

新增通用字段 `attribution: action_response | world_beat`。默认是玩家行动回应；无意图、无对象约束的自动重效果卡必须显式声明 `world_beat`。当前故事的开场压力、侍女便签、火势升级、管家到达、午夜毁证、终幕集合和结局路由均标记为世界节拍。

TurnResult 分开记录玩家回应、世界节拍和 world step 反应。叙事事实清单分别披露；玩家无专门回应时给出明确事实，禁止渲染模型把节拍写成行动成果。玩家判定档位也不再由 `world_beat` 类型抬高或压低。

### 事实清单补齐时间和位置语义

- 行动目标改为“名称 + 感知安全的位置说明”，只描述当前同场、口袋、行动发生时的场景或已离开可见范围，不泄露隐藏坐标。
- 最近事件改名为“过去回合发生（非本回合）”，并保存 TurnResult 提交前的事件窗口，避免把本回合提示重复当成过去背景。
- 渲染 prompt 明确禁止把过去事件写成正在发生。

## 实现情况

- LLM 空提议回退内容 `fallback_proposal`，新增“LLM 路径不弱于菜单路径”回归测试。
- custom 未命中作者交互时统一产生 `action.unauthored_attempt`，报价显示“没有把握”。
- CLI 在 LLM 模式下把未知格式的整行输入直接送入理解层；有未决澄清时优先把裸文本当回答，不再经过旧意图解析器。
- LLM 模式模板回退不再提示 `observe family_portrait` 等结构化命令。
- DeepSeek 叙事空响应自动重试一次，仍为空才回退模板；usage 合并记录。
- validator 扩展为检查无行动接地的重效果卡，`world_beat` 是显式豁免身份。
- 补 Python 3.9 下 Pydantic 解析 `X | None` 所需的 `eval-type-backport` 条件依赖。

## 同日第二批：真实试玩复查——归因修复没有覆盖触发与模板回退

修复后真实 DeepSeek 试玩仍出现“询问薇拉遗嘱，却只看到侍女送便签”。trace `b13af99eb5fc` 证明理解层正确输出 `negotiate + heir` 和 `heir.trust +1`；实际提交却同时触发 `opening_pressure + maid_warning`。第一回合没有 narration 记录且无 error，说明叙事重试后仍为空，CLI 使用旧的合并 hints 模板回退。

这说明上一批只解决了归因数据结构，没有闭合体验：

- `world_beat` 只分类、不阻止执行；`maid_warning` 仍以初始 `maid.trust >= 2` 搭任意回合触发。
- 与薇拉交涉只有软状态变化，没有专属 storylet 或通用行动回应，因此事实清单里仍没有薇拉说了什么。
- 模板回退继续读取合并后的 `narrative_hints`，绕过了新归因字段。

本批修复：

1. `maid_warning` 改为 `action_response`，必须 `negotiate + maid`；与其他角色交谈不再发放侍女便签、线索和路线 flag。
2. 侧梯转场不再依赖侍女事件。玩家实际选择侧梯时设置 `side_door_found`，随后既有 world rule 让艾拉使用仆役路线移动；在走廊首次与她交谈可按有序级联触发 `maid_warning + maid_lends_key`，主路线回合数不增加。
3. resolver 在没有专属行动 storylet 时，用 `fallback_narrative` 生成带实际目标名称的行动回应，例如“针对薇拉小姐……”。世界节拍不能再成为唯一输出。
4. 模板回退先输出行动回应，再以“与此同时”分隔世界节拍、以“随后”分隔自治世界反应；兼容旧 TurnResult 才读取合并 hints。
5. validator 将“action_response 无 intent/object 接地”列为通用警告，不再只检查重效果。
6. DeepSeek 两次空叙事后写入 `narration_fallback: empty_response`，以后不再需要靠 trace 缺行推断模板回退。

验证：74 项测试通过，内容校验 0 警告，4 条 walkthrough 全部通过。Mock 模板冒烟确认与薇拉交涉先显示薇拉目标回应，再单独显示管家世界节拍，且不触发侍女事件。

## 同日第三批：清除通用运行时中的故事专属词汇

都市日常故事接入后，CLI 仍显示“全家画像”“薇拉小姐”“仆役侧门钥匙”等旧故事示例，退出时也固定输出“离开庄园”；renderer 的结构化兜底提示还写死了 `family_portrait`。这些文本不是内容 YAML 提供，而是通用运行时残留的样板故事依赖。

本批处理：

1. CLI 帮助改用 `<意图编号或 ID>`、`<物品>`、`<目标>`、`<出口>` 等内容无关占位符。
2. renderer 的结构化兜底提示改用 `<意图 ID> <对象 ID>`，不再引用任何内容对象。
3. CLI 不再默认载入某个故事 ID。未传故事路径时扫描 `content/*.yaml`，只有一个则直接载入，多个则按文件顺序展示标题供玩家选择；显式路径保持兼容。
4. 退出语改为“本次游玩结束”。
5. 新增通用性回归测试，扫描 `server/` 和 `tools/`，禁止已知故事 ID、角色名和物品名重新进入通用 Python 源码；同时覆盖故事发现和选择。

验证：77 项测试通过；两个故事共 8 条 walkthrough 全部通过；无参数 CLI 能列出两个故事并正确进入所选内容。都市故事校验仍有 3 条“场景不可达”静态误报，原因是 validator 尚未把通用 `move + exits` 计入可达图，与故事专属词汇清理无关。

## 同日第四批（补记）：故事 #2 与首次真实试玩暴露的能力层缺口

### 都市日常故事落地

新增关系驱动的都市日常故事《晚风中的一桌饭》（`rooftop_supper`），用同一套 schema 验证没有反派、暴力和重大秘密的低烈度体验。故事包含 4 个场景、5 名角色、3 件受跟踪物品、21 张 storylet 和 3 个结局；玩家要在晚饭窗口结束前帮陈阿姨在天台摆饭，可以只完成安静的小桌，也可以在不勉强任何人的前提下邀请小雨和阿禾。

内容提供两种铺桌物路线（便利店野餐垫 / 洗衣店格布）、帮助与对话两种邀请方式，以及共享晚饭、小桌晚饭、计划散去三档收束。4 条 walkthrough 覆盖两种物资、两档成功和时间耗尽结局。移动到达卡只负责行动回应和成功归因，位置仍由通用 `move + exits` 提交。

### 首次 DeepSeek 试玩复盘

真实 trace `932c31db448b` 暴露了比内容分支缺失更重要的问题：自然语言入口看似自由，但 canon / mechanical 结果仍高度依赖精准命中作者 storylet。

1. 玩家“只问罗叔借桌垫”被正确理解为 `talk + clerk_luo`，报价和提交都只有 `clerk_luo.rapport +1`，没有 storylet、事实或 `move_items`；野餐垫始终由罗叔持有。旁白却写成“伸手去够收银台上的桌垫”，把玩家想做的事写得像已发生事实，造成“似乎借到了、背包却没有”的错觉。
2. 当前唯一会转移野餐垫的作者路径是 `help + clerk_luo + carton_stack`。这条三元触发既没有 `director_hint` 暴露，也不覆盖语义完全合理的“向罗叔借桌垫”，说明内容动作面过窄。
3. `carton_stack` 是环境对象而非可携带物品；系统没有通用拾取、借用或环境对象加工能力。“借纸箱”“拿纸箱”无法产生物品转移。普通 `talk` 只应用熟络兜底且不会标记 unauthored，`custom` 才会明确提示 `action.unauthored_attempt`。
4. Planner 在澄清中主动建议“借废纸箱拆成纸板”或“请阿禾帮忙”，但这些路线没有作者事件或机械能力。当前感知只告诉模型“有哪些对象”，没有告诉它“哪些因果 affordance 可以可靠执行”。
5. 计划目标 `borrow_table_mat_from_clerk` 与预演结果“仅熟络 +1”明显不一致，现有验证只检查 intent、对象与 patch 权限，没有检查目标是否被预计结果覆盖。
6. trace 收到的两次玩家文本分别退化为 `5废纸箱` 和 `和打个招呼之后拿纸`，再次证明终端中文输入存在丢字；它解释了“借 5 个纸箱”等怪异理解，但不是物品无法取得的根因。

### 架构判断

感知墙、状态账本、报价后提交、canon 权限隔离和 storylet 世界节拍这些底层原则仍然成立。问题出在中间的动作执行层尚未完成：当前 LLM 只做“自然语言 → 单个 intent + 对象 + 软状态提议”，基础机械结果（物品、位置、事实、flag）仍主要由 storylet 承担。Storylet 因而同时充当剧情卡和基础动作实现，复杂目标只能依赖作者枚举精确路径。

这目前是核心能力未实现的阶段性阵痛，但如果继续通过增加精确 storylet 修补，就会固化成架构问题。目标结构应是：

```text
玩家长期目标
→ 可持续、可重规划的多步计划
→ 对话 / 请求物品 / 拾取 / 交付 / 加工 / 移动等通用能力
→ 前置条件、权限和目标—结果一致性验证
→ 原子提交状态账本
→ Storylet 只响应已提交事实并增加剧情节拍
→ 旁白忠实渲染
```

### 后续优先级

1. 先修公平性：玩家输入只能作为“尝试”，旁白不得把未提交目标写成结果；无作者事件但有 fallback hint 时也要明确披露“没有取得目标成果”。
2. 在报价前增加目标—结果一致性检查：请求物品但预演没有物品变化时，必须明确降级、拒绝或重规划，不能仅用熟络变化冒充部分达成。
3. 向 Planner 暴露作者声明的可执行 affordance，禁止澄清问题把纯推测路线说成可行建议。
4. 定义首批正式能力模块：`request_item` / `take_item` / `give_item` / `transform_object`，由通用权限和内容条件控制 `move_items`，不把 canon 写权限交给 LLM。
5. 引入跨回合计划记忆与失败重规划；每回合仍只原子提交一个动作，但保留长期目标和下一步。
6. 对话模块负责请求、拒绝、条件交换和承诺，物品模块负责实际所有权变化；Storylet 回归关键剧情事实与导演节拍。

本次只完成诊断和记录，没有为纸箱或桌垫增加临时特判。下一批应先解决通用目标—结果一致性和叙事事实约束，再决定都市故事需要补哪些内容 affordance。
