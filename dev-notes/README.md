# 开发记录

这个目录用于记录 AIRPG 每天开发中的思考、决策、计划和实现情况。

## 记录约定

- 文件名使用 `YYYY-MM-DD.md`。
- 同一天的内容持续追加到同一份文档，不重复创建。
- 重点记录问题、判断依据、最终结论和实际实现，不写流水账。
- “下一步”保持在 2–4 项，每项对应一个可验收的阶段，不拆成过长的任务列表。
- 已改变的架构决定要说明原因；尚未验证的想法要明确标记为假设。

## 建议结构

```markdown
# YYYY-MM-DD 开发记录

## 今日主题
## 问题与思考
## 形成的结论
## 实现情况
## 下一步
## 验证结果
```
