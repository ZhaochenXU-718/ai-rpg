# 2026-08-03｜功能导向的行编辑模块设计

## 今日主题

在旁白 prompt 已从“去除 AI 特征”纠正为“去除无功能的表达，同时保护节奏、
人物和心理运动”之后，继续设计一个可选的初稿后编辑模块。本篇只记录职责、
prompt 来源与接入形态；模块尚未实现，所有运行效果仍待 `shadow` 样本和试玩
验证。

## 问题与思考

### 为什么不能再做一套“AI 特征清单”

此前的表面禁令会把“常见于 AI 文本”误当成“在当前段落中必然无效”，从而把
有功能的停顿、重复、心理解释和句子层次一并删掉。结果虽然更短、更整齐，却
容易退化为动作与台词组成的简报体。

因此编辑器不能采用“命中模式 → 直接删除”的工作方式。任何外部规则都只能
触发检查，最终是否修改必须通过功能判断：删除或改写后，是否损失信息、人物、
心理变化、节奏、空间定位、潜台词、悬念或叙事视角。只要会损失其中一项，就
应保留或仅做局部修改。

### 为什么参考开源 skill

从零凭感觉撰写编辑 prompt，容易再次把个人偏好误写成普遍规则。开源写作
skill 汇集了编辑实践和对 LLM 写作失误的长期归纳，适合作为人类先验来源；
但多数面向英文非虚构文本，不能整份拼接或直接翻译进中文互动小说 prompt。

暂定参考来源及取舍：

- `haowjy/creative-writing-skills`：作为最高层写作原则。采用“相信读者”、
  “经济性不等于极简”、保护叙事沉浸、句子审美、人物模拟、阅读流畅和
  好奇心等原则；采用 `story-review` 对行编辑与发展性编辑的职责划分。
- `conorbronsdon/avoid-ai-writing`：采用“先识别再判断”、结构与节奏比词语
  黑名单更重要、只做必要的局部修改、已有自然段落不动；不采用英文词频表、
  破折号数量、博客标题与段落格式规则。
- `blader/humanizer`：采用保留原有信息、不发明事实、匹配原有声音、不要把
  文本磨成无菌统一风格；不采用为了“像真人”而注入第一人称、观点、幽默或
  刻意瑕疵的做法。
- `stephenturner/skill-deslop`：只借鉴 directness、rhythm、trust、
  authenticity、density 等检查维度，不照搬其面向科学和技术写作的例子。

Hallmark 等设计类 skill 可借鉴“原则 + 检查表 + 正反例”的组织方式，但内容
本身不进入散文编辑 prompt。

上述来源只能提供诊断先验，项目自己的功能保护规则拥有最高优先级。正式落库
前需记录每个来源的具体 commit、许可证、采用/排除项和中文化改写；运行时不
联网拉取，也不自动跟随上游 `main`。当前确认 `humanizer` 与
`avoid-ai-writing` 为 MIT，`creative-writing-skills` 为 Apache-2.0；若
直接翻译或改写其文本，须保留相应许可证与归属说明。

## 形成的结论

### 1. 模块是全局可选能力

编辑器属于引擎运行时，不进入作品 YAML，不要求创作者提供 `style_bible` 或
`prose_profile`。暂定三种模式：

- `off`：默认。完全沿用当前生成和流式输出路径，不增加调用、成本和延迟。
- `shadow`：编辑器生成候选稿并记录对照，但玩家仍看到初稿；用于建立回归
  样本、观察误伤和校准 prompt。
- `on`：仅在候选稿通过保护检查后输出编辑稿；调用失败、空输出、格式异常或
  保护检查失败时自动回退初稿，不能阻塞一个回合。

`shadow` 是从设计进入生产前的必要阶段。没有足够对照样本前，不把默认值改为
`on`。

### 2. 编辑器只做行编辑

输入是叙事器已完成的初稿。编辑器不是第二个作者，也不是导演或事实修复器。

必须保持：

- 事件、事实、发生顺序、因果和行动结果；
- 人物位置、动作执行者和对话说话者；
- 角色当前的知识边界、线索披露程度和不确定性；
- 玩家行动及其能动性；
- 人物立场、关系、态度及心理变化方向。

可以处理：

- 已表达过、再次解释却没有增加意义的内容；
- 动作已完整表现情绪后，对同一情绪的机械命名；
- 多个近义修饰语只增加音量、不增加层次的堆叠；
- 不承担空间、人物、气氛、节奏或伏笔功能的泛化描写；
- 机械整齐的句式、连续同形短句制造的虚假戏剧感；
- 对话中双方和读者都已知道、且不承担人物功能的信息复述。

必须保护：

- 有强调、回声或人物意义的重复；
- 停顿、迟疑、过渡和必要的心理运动；
- 人物独有的声音、POV 的主观解释；
- 长短句变化、段落呼吸和句子层面的审美；
- 同时承担人物、氛围、空间、伏笔等多重功能的细节；
- 有意保留的歧义、潜台词、悬念和信息空缺。

编辑目标不是缩短文本，而是让保留的表达承担功能。如果初稿没有明确问题，
应原样返回。

### 3. Prompt 采用有优先级的规则合成

prompt 不直接拼接完整 skill，按以下层次组织：

1. **身份与边界**：中文互动小说行编辑，不续写、不重构、不改变内容。
2. **不可变约束**：事实、人物、知识边界、披露程度、玩家能动性等不得改变。
3. **功能判断程序**：先判断删除会损失什么，再决定保留、局改或删除。
4. **候选问题库**：重复解释、情绪复述、空泛气氛、机械句式等只作为检查
   信号，不是硬禁令。
5. **保护清单**：节奏、人物声音、心理运动、POV、潜台词和多功能细节。
6. **正反例**：明确展示“较长但有功能”的段落不能被压成动作简报，防止模型
   把简洁误解为短促。
7. **输出契约**：只输出最终正文；不得输出分析、标题、修改说明，也不得为了
   制造“人味”添加新内容。

关键反例应保留此前讨论的教授段落：把“指尖停顿 + POV 对克制的判断 + 二十年
研究形成的反应 + 私下警告”压成“手停下 + 下课来找我”，虽然更短，却损失了
人物心理、观察视角、关系张力和信息层次，属于失败编辑。

### 4. 接入与失败语义

概念链路：

```text
旁白生成初稿
    ↓
编辑器关闭？── 是 → 当前输出路径
    │
    否
    ↓
行编辑生成候选稿
    ↓
保护检查
    ├─ 通过 → 输出候选稿
    └─ 失败 → 回退初稿
```

`on` 模式必须先缓冲完整初稿再编辑，因此会增加首字延迟；`off` 模式不得改变
当前流式体验。`shadow` 模式的结果不影响玩家回合，是否在回合提交后异步执行
留待实现阶段结合现有 trace/worker 结构决定。

记录项至少包括：原稿、候选稿、prompt 版本、模式、是否回退及原因、字数变化
比例和保护检查结果；不记录模型内部推理。

现有物理事实抽取可以发现一部分事实漂移，但不能证明人物态度、披露程度、
心理运动等软语义全部保留。按本目录约定，prompt 中的“不得改变”只是缓解，
不是控制。`on` 模式的完整保护检查仍是待设计问题；在此之前以默认 `off`、
`shadow` 对照和失败回退限制风险，不能宣称编辑安全已解决。
