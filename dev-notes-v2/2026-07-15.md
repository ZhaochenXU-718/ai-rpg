# 2026-07-15 开发记录：Phase 1 批次 A / B / C 拆除与协议收敛

## 今日主题

完成叙事优先转向的第一个拆除批次：先让活动内容停止声明旧机械判定面，再进入引擎代码删除。此次不新增事实抽取、铁律校验、Director v2 或 NPC agent。

## 形成的结论

- 内容文件显式声明 `content_profile`：活动故事使用 `narrative_first`，历史机械样本使用 `pre_pivot_archive`。校验器按档案分别检查，避免为了兼容旧引擎继续污染新内容。
- 叙事优先 NPC 必须声明 `motivation`、`voice` 与定性的 `initial_relationship`。数值 `rapport` 不再属于内容状态。
- 叙事优先 storylet 只允许 `world_beat` / `after_world` 锚点，并且不能再使用 `intent`、`intent_any`、`object_any` 或 `object_all` 作为行动路由条件。
- 旧运行时尚未在本批删除。仍有价值的旧引擎测试通过内存适配器获得最小 legacy 字段，活动 YAML 本身保持纯净；该适配器将在批次 B 随旧引擎测试一起退役。

## 实现情况

### 内容拆除

- 《晚风中的一桌饭》移除 `intents`、`resolution_limits`、`quote_warnings`、`items.*.request_policy` 与 `scenes.*.suggested_intents`。
- NPC 数值 rapport / fatigue 和公开数值状态栏退役，改为人物卡中的定性初始关系与说话方式。
- 19 个旧 storylet 收缩为 6 个事实锚点。普通移动、对话、帮忙、借物和铺桌不再由 action storylet 白名单授权。
- 开放场景夹具完成同样的字段清理，并保留 Local Canon 原型与预算。
- 《午夜前的档案室》标记为 `pre_pivot_archive`，继续作为旧机械运行时和历史 walkthrough 的只读样本，不参与叙事优先内容回归。
- 退役已经无法表达新循环的屋顶结构化 walkthrough；档案室历史 walkthrough 保留到批次 B。

### 校验器与测试

- 校验器新增内容档案区分、叙事优先退役字段检查、NPC 人物卡必填检查和锚点 storylet 检查。
- 叙事优先内容图不再报告“某 flag 没有被 storylet 设置”：未来 flag 也可能来自事实抽取与原子提交，静态 storylet 图无法据此判死。
- 旧 social / suggestions / Director / Local Canon 测试不再直接依赖活动故事中的退役字段；测试内存适配器只负责维持批次 B 前的过渡期覆盖。

## 验证结果

- 全量测试：`130 passed`。
- 《晚风中的一桌饭》、开放夹具和封存的《午夜前的档案室》内容校验均为 0 error / 0 warning。
- 档案室四条历史 walkthrough 全部通过。
- `git diff --check` 通过。

## 批次 B：引擎拆除与叙事优先提交缝

### 本批目标

删除活动运行时里的前验机械判定面，让自然语言直接进入散文生成；保留感知墙、Director / Local Canon、原子状态提交、锚点扫描、checkpoint / 撤回 / 分支和 trace。此批只建立后验管线的提交缝，不冒充已经完成 Phase 2 的事实抽取与铁律校验。

### 已删除

- `quote.py`、`limits.py`、`social.py`、`capability_effects.py`、`capabilities.py` 与 `llm_loop.py`；活动运行时不再报价、按意图路由、调用静态能力或裁剪数值软状态。
- `walkthrough.py`、`tools/check_walkthroughs.py` 与两份结构化 walkthrough；这套格式编码的是旧的意图 / 对象执行语义，不能继续作为叙事优先循环的验收标准。
- 旧 social / router / llm-loop 测试和批次 A 的 legacy 内容适配器；保留资产改用叙事优先接口重新覆盖。

### 新提交骨架

- 新增内部 `FactBatch`：包含玩家原话、散文、待提交状态变化、事实与可见引用。`commit_facts` 原子应用批次，再扫描 `after_world` 事实锚点、Local Canon 过期和结局。
- `GameSession` 只接受 `narrative_first` 内容；每次提交仍写入 checkpoint，撤回恢复父提交并创建保留历史的新分支。
- CLI 只保留自然语言、`ideas` / `idea <n>`、`facts`、`who`、`state`、`undo` 和 `timeline`。提案卡是可编辑散文，不再冻结 ActionPlan 或预验证结果。
- Director Beat 和 Local Canon 重新接到同一回合提交；候选人物移动、原型 / 预算 / 命名 / 冲突检查仍由代码复验，provider 失败不会撤销已提交的玩家回合。
- 活动内容继续只保留事实锚点；`world_rules` 自动移动字段也从叙事优先档案退役。`pre_pivot_archive` 可由校验器读取，但不能启动新会话。

### 诚实边界

Phase 2 尚未实现，因此 CLI 普通回合构造的是**无状态变化的散文批次**：可以描写玩家正在尝试，但不能声称移动完成、物品转移、秘密披露、人物承诺、生死变化或锚点推进。`FactBatch.state_changes` 当前只供内部回归和保留模块接缝使用，不能视为安全的外部输入；下一阶段必须在其前方加入结构化事实抽取、代码级铁律冲突检查和有限重生成。

旧 `ActionPlan`、capability 与旧式 suggestion schema 仍暂存在 provider 协议层，活动 `session` / `resolver` / CLI 已不再消费。它们将在批次 C 连同相关 prompt 和契约文档一起删除，避免本批同时改动运行时与所有外部协议面。

### 验证结果

- 全量测试：`59 passed`。
- 《晚风中的一桌饭》、开放夹具与封存的《午夜前的档案室》内容校验均为 0 error / 0 warning。
- mock CLI 冒烟通过：自然语言散文回合、开场事实锚点、Director 反应、`ideas` 提案卡与退出流程均正常。
- 删除模块引用审计无命中；`compileall` 与 `git diff --check` 通过。

### 下一步

1. **批次 C｜协议收敛**：删除 ActionPlan / CapabilityAction / ValidationResult 等前验协议及 DeepSeek 旧计划 prompt；将 narration、Director 与可编辑提案卡改为原生叙事优先 provider 接口。
2. **批次 C｜契约同步**：更新 authoring-contract、content-schema、engine-principles 和架构图，明确事实锚点、铁律扩展点与 walkthrough 的替代验收形式。
3. **Phase 2｜最小后验闭环**：定义事实抽取协议，实现移动 / 物品 / 披露 / 承诺的代码级冲突检查、重生成上限与原子提交，在开放夹具跑通“请求防雨布”的真实闭环。

## 批次 C：协议收敛与契约同步

### 本批目标

删除 provider 层最后一组前验计划语义，让散文、提案卡、Director 与未来 NPC agent 都使用叙事优先协议；同时把多主体感知边界和后验提交契约写进代码与文档。本批仍不提前实现 Phase 2 的事实抽取或铁律冲突检查。

### 协议与 provider

- `llm_protocol.py` 升级为 0.2：删除 `ActionPlan`、`CapabilityAction`、旧 `ValidationResult`、风险报价和旧提交结果；新增带 `state_revision` 的 `FactBatch`、`IronLawViolation`、`DirectorPlan`、`NpcTurn`、`CommittedTurn` 与权威来源枚举。
- provider 接口收敛为 `render_narrative`、`propose_suggestions`、`propose_director` 和预留的 `propose_npc_turn`。DeepSeek prompt 直接生成散文、轻量提案卡与 Director 计划，不再先构造机械计划。
- 提案卡只包含可编辑的行动文本、简短理由与可能触及的铁律领域；它是灵感入口，不是预验证结果或行动白名单。
- Director 请求改用已提交回合、作者边界与 Director 感知；返回 `DirectorPlan`，现阶段继续复用既有人物移动和 Local Canon 的确定性复验。

### 状态与感知

- `FactBatch` 进入正式协议层；`GameSession` 会在原子工作副本创建前拒绝陈旧的 `state_revision`，避免基于旧世界视图提交事实。
- 感知改为 `PerceptionSnapshot` / `PerceivedEntity`，并提供通用的主体构造器。玩家只看到公开信息；NPC 感知拥有自己的位置、已知事实、动机、口吻、初始关系和自身秘密，为后续 NPC agent 保留私有输入边界。
- 玩家散文 prompt 显式接收玩家感知快照；测试覆盖 NPC 私密秘密不会泄漏进玩家快照。

### 契约文档

- 新增 `narrative-first-protocol.md`，旧 `llm-action-plan-protocol.md` 随前验协议删除。
- 重写作者契约、内容 schema、引擎原则、状态时间线以及提案卡 / Director 文档，统一事实锚点、铁律扩展点、revision 和 walkthrough 替代验收方式。
- 重绘 `docs/assets/final-architecture.svg`，总图现在展示“生成 → 抽取 → 铁律校验 → 原子提交”，不再展示前验能力路由与报价。

### 诚实边界

当前协议已经能表达后验闭环，但还没有不可信散文到 `FactBatch` 的抽取器，也没有移动、关键物品、秘密披露和人物承诺的完整冲突检查器。CLI 仍只提交散文与可信内部锚点；`NpcTurn` 是下一阶段接口，不代表 NPC 独立回合已经运行。

### 验证结果

- 全量测试：`65 passed`，包含陈旧 `FactBatch`、Director plan 信封和 provider 提案卡不可复用的 revision 回归。
- 《晚风中的一桌饭》、开放夹具与封存的《午夜前的档案室》内容校验均为 0 error / 0 warning。
- mock CLI 冒烟通过：启动文案、原生提案卡、采用卡片后的散文回合、事实锚点、Director 响应与退出流程正常。
- 旧计划协议与已删除模块引用审计无运行时代码命中；本地 Markdown 链接、SVG XML 与 920×720 浏览器渲染、`compileall`、`git diff --check` 均通过。

### 下一步

1. **Phase 2｜事实抽取器**：从已生成散文提取移动、物品转移、秘密披露、人物承诺和锚点事实，并绑定输入 revision 与来源引用。
2. **Phase 2｜铁律检查与重生成**：代码级检查在场 / 邻接、所有权、披露权限、锚点顺序和世界边界；冲突时携带结构化 violation 有限重生成。
3. **Phase 2｜开放夹具闭环**：跑通“周师傅答应明天给防雨布”的抽取、提交、记忆与后续兑现验收，替代旧结构化 walkthrough。
