# 2026-08-01｜记忆检索与导演职责的形态判断

## 今日主题

评估两个方向性问题：记忆侧是否需要引入向量数据库；剧情推进侧是否需要导演
agent。两者结论一致：**方向对、形态错**——都先用已有结构承接职责，等长局
实测给出升级证据再加重。本篇只记录判断，均未实现，全部按假设对待。

## 问题与思考

### 记忆：缺口是检索，不是存储

当前三层（M1 原始事件全量保留 → M2 滚动压缩 → M3 预算拼装）有一个结构性
盲区：**事件一旦被压缩，原文永远不会再回到 prompt**，只剩有损摘要
（rolling_summary 进上下文 ≤900 字、6 条 open_loops、6 人×2 条笔记、4 场景）。
20 回合左右的局（record/731.txt）撑得住；可预期的失败模式在 50+ 回合：
玩家提起远处回合的承诺、旁白现场发明的专名（"真名登记""七项程序"）、
具体数字，引擎捞不回原文，模型凭 900 字摘要脑补，产生设定漂移。

**否掉向量数据库**：语料规模极小（单局几百个事件，本来就全在内存的
`MemoryState` 里），且 `MemoryEvent` 已有现成结构化索引字段
（`participants` / `references` / `scene_before/after`）。为这个规模引入
向量库是给不存在的问题上基建。

**采用的路径**（按序）：

1. **实体索引召回**：人物/物品/场景重新进入感知、或玩家输入提到某实体时，
   从已压缩的 M1 事件中确定性捞出涉及该实体的最近 K 条原文片段，作为
   "相关旧事"小字段进上下文。纯代码、零额外 LLM 调用，符合"编排靠代码"
   的引擎原则。
2. **专名表（canon glossary）**：旁白发明的新设定词现在只活在散文和有损
   摘要里。事实抽取管线已存在，可顺路沉淀"本回合新专名 + 一句话定义"为
   持久词表，随 `known_facts` 注入。防设定漂移最便宜的一招。
3. **向量检索只在有证据后**：实体索引 + 关键词都覆盖不了（模糊语义指代
   "上次那个梦"）且实测确认召回失败时再上；届时也是进程内方案
   （sqlite-vec 一类），不是独立向量数据库服务。

另记：NPC 亲历记忆是文档明确的留白（M1 只建玩家记忆），长线人物关系全靠
6×2 条 character_notes——这比向量库更早会疼。

### 剧情推进：需要导演职责，不需要每回合导演 agent

拔掉静态场景目标（e57fba2）之后，**没有任何东西在跟踪"故事当前在讲什么、
节奏处于什么状态"**，只剩 open_loops 这个被动列表。缺的三件事都是导演
职责：节奏感知（日常回合连续太多该升压了吗）、升级判断（哪条 open loop
该被推向下一拍）、长线呼应（伏笔回收）。

**否掉每回合导演 agent**：串行 LLM 调用直接加在玩家等待延迟上；多一个
失败面；与"确定性编排 + 软性 LLM 输出"的设计哲学冲突。

**采用：导演作为 M2 扩展**。M2 本来就每 ~4 回合跑一次、读全部近期事件、
判模块状态，让它顺路多输出一个小的"导演提示"（张力评估、建议升级哪条线、
节奏建议，一两句话）。两条消费路径：

- 作为软字段进旁白 payload（与 candidate_modules 并列）；
- 给确定性编排器一个偏置信号（如提前/推迟解锁 pressure 类别，替代现在
  写死的 `min_turn=6`）。

全程非权威、代码把关转换、失败不影响回合——与现有 `module_updates` 的
处理方式完全同构。按记录约定，导演提示属于 prompt 层缓解，不算控制。

**升级条件**：长局实测证明低频形态不够（如需要回合级即时转折判断）再拆成
独立 agent，届时有数据知道它该做什么。

## 当日实现：旁白流式输出与后台记忆压缩

背景是延迟诊断（旧 trace 实测）：一次输入 = 旁白 ~6s + 事实抽取 ~4s 串行，
偶尔再叠 ~5s 同步记忆压缩；全程无流式，感知延迟等于完整延迟。本批落地
两项改进，都不改变回合语义。

### 1. 旁白流式输出

- `llm.py` 新增 `NarrativeStream` 监听器（`delta`/`restart` 均为可选空操作）；
  `render_narrative` 增加 `stream` 参数，DeepSeek/Kimi 走 SDK
  `stream=True` 逐块转发 content delta（reasoning 不进流），transport
  测试路径整段发一个 delta 保持语义一致。
- **撤回信号统一为 restart**：provider 内部重试（length_exhausted）、管线
  重生成（physical_conflict）、降级 fallback（narration_fallback）都先
  restart 再送替换候选；由监听器决定是否需要提示（屏幕上没字就沉默）。
  商业式"流式 + 罕见撤回"，铁律校验语义不变——撤回文字已被玩家看到，
  但回合仍只在校验通过后提交。
- CLI `ConsoleNarrativeStream` 即时打印；提交后只补打印物理回执与换场
  （`render_turn_tail` 从 `render_turn` 拆出，输出逐字节不变），散文不再
  二次打印；无流式内容时整段打印保底。

### 2. 后台记忆压缩

- `memory_pipeline.py` 拆出计划/构建请求/应用三段共享辅助；同步入口
  `maybe_compact_memory` 行为不变。
- 新增 `BackgroundMemoryCompactor`：`kick`（提交后，主线程）做计划与
  不可变请求快照，慢调用交给单个 daemon worker；`poll`（CLI 每轮循环
  开头，主线程）应用完成的结果。**session 从不被工作线程触碰**。
- 在途时新 kick 直接跳过（等同一次被跳过的同步尝试）；撤回换分支后返回
  的结果按 stale 丢弃、不记冷却（trace: `memory_compaction_stale`）；
  真失败仍走原有 3 回合冷却。provider 懒初始化 client 加锁（前后台并发）。

### 顺手修复

- test_prompt_routing 两处断言找 "不是 A，而是 B"，而 88f96ae 提交的
  prompt 实文是 "不是...而是..."——HEAD 上就红的存量失败，断言改为与
  实文一致。

### 验收

166 个测试通过（新增 15：provider 流式 5、管线 restart 1、CLI 显示 5、
后台压缩 4）；mock provider CLI 冒烟通过，quit 不挂线程；
memory-and-summaries 增补"后台执行"一节。

## 当日实现（二）：Web 客户端第一版

需求：网页 UI，文字输入 + ideas 弹出 + 点选直接执行 + 刷新重新生成，
为后续发布到网站做准备。

### 形态

- **零新依赖**：`server/web.py` 用 stdlib `ThreadingHTTPServer`；前端
  `web/index.html` 单文件自包含（无构建、无外部资源）。
- **可测试内核与传输层分离**：`WebGame` 持有 session/provider/compactor，
  RLock 串行化所有会话访问——持锁的请求线程就是"玩法线程"，后台压缩的
  kick/poll 契约因此继续成立；HTTP handler 只做翻译。
- **回合走 SSE**：`/api/turn` 与 `/api/idea` 以 `data:` 帧推送
  delta/restart/player_text/committed/error 事件，复用 CLI 同一套
  `NarrativeStream` 撤回语义；客户端断开不 abort 回合（emit 吞掉
  OSError，回合在服务端提交，刷新后从历史恢复）。
- **历史恢复**：`/api/state` 返回开场文本 + `memory.events` 的
  player_text/narrative，对局记录刷新不丢。
- **提案生命周期与 CLI 一致**：服务端缓存 suggestion set，state_revision
  变化即失效；`refresh` 强制重新生成；点选走 `prepare_suggested_action`
  过期校验并记录 `suggestion_selected` trace。

### 发现并修复

- Web 端 restart 处理最初无条件显示"已撤回"提示；mock provider 走
  narration_fallback 时屏幕上还没有字也提示。修复为与 CLI 监听器相同的
  语义：屏幕无字则沉默。

### 验收

172 个测试通过（新增 WebGame 6 个）；浏览器端到端（mock provider）验证
发送回合、流式显示、提案弹出/点选执行/刷新、刷新页面恢复历史。
`.claude/launch.json` 增加 airpg-web-mock 配置。真实 provider 的网页
流式体验待 DeepSeek/Kimi 试玩验证。
