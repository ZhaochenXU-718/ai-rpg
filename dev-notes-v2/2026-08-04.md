# 2026-08-04｜可选行编辑器第一版

## 今日主题

实现 2026-08-03 设计的初稿后行编辑模块。目标是先建立可关闭、可观测、失败
可回退的完整链路，不把“编辑后一定更好”当作前提。默认仍为 `off`，真实
provider 应先在 `shadow` 模式积累对照样本。

## 形成的结论

### 三种模式进入统一回合管线

- `off`：不调用编辑器，旁白继续按原路径逐块流式输出并做一次事实抽取。
- `shadow`：初稿照常流给玩家；初稿物理校验通过后生成并记录编辑候选，但
  始终提交初稿。第一版同步执行，因此会延后 committed 事件，但不影响首字。
- `on`：先缓冲旁白初稿并完成物理事实校验，再生成编辑候选。候选通过文本
  guard 后重新抽取物理事实；只有编辑前后 `state_changes` 完全一致才采用，
  否则回退已验证初稿。最终正文通过一个完整 delta 发给 CLI/Web。

CLI 与 Web 都新增 `--prose-editor off|shadow|on`，默认值为 `off`；该设置是
运行时能力，没有进入作品 YAML，也没有新增创作者配置。

### 编辑器输入保持最小

`ProseEditRequest` 只携带玩家本回合行动、上一回合公开正文、本回合初稿和当前
可见名称组成的保护词集合。编辑器看不到故事蓝图、人物私密卡和完整软记忆，
不能把第二次 LLM 调用变成另一轮续写。

DeepSeek/Kimi 共享 `prose-edit-v1` 中文 prompt。prompt 以“经济性不等于极简”
和功能判断为最高原则，候选问题只触发检查；显式保护人物声音、心理运动、
POV、节奏、潜台词和多功能细节，并包含“较长心理反应被压成动作简报”的失败
反例。外部 skill 的具体版本、采用/排除项和许可证记录在
`docs/prose-editor.md`，运行时不加载外部内容。

### 第一层代码 guard

`server/engine/prose_editor.py` 拒绝以下明显越界：

- 空输出、Markdown 围栏或“修改后”等编辑说明；
- 非空白字符压缩到初稿 65% 以下，或扩张到 120% 以上；
- 初稿中出现的当前可见名称被删除，或原稿未出现的可见名称被加入；
- 数字被增加、删除或改写。

这些规则只拦截粗粒度失控，不是新的语言禁令，也不裁决文学质量。物理双重
抽取只保护人物位置和关键物品归属；人物态度、披露程度、心理运动等软语义仍
无法由代码证明等价。因此 `on` 仍是实验模式，不能宣称编辑安全已解决。

### 可观测与失败语义

新增 `prose_editor`、`prose_editor_selection`、
`prose_editor_fact_check_error` trace；原有事实抽取和物理校验记录增加
`candidate_kind=draft|edited`。编辑调用失败、空输出、guard 拒绝、编辑稿事实
抽取失败或物理变化不一致，都提交已验证初稿，不让可选模块阻塞回合。

## 实现情况

- `llm.py` 增加行编辑请求/响应与 provider 能力，Scripted provider 支持编辑
  队列，mock provider 使用恒等编辑。
- DeepSeek/Kimi 增加共享 prompt、独立 call policy、版本和一次空结果修复重试。
- `fact_pipeline.py` 抽出共用事实抽取/校验辅助，并接入三种编辑模式和物理签名
  比较。
- CLI、Web 增加运行时开关；README 与 `docs/prose-editor.md` 说明成本、流式
  差异、guard、trace、来源和已知边界。
- 新增/扩展 provider、管线、guard、CLI 与 Web 测试。

### Web 开发对照面板

为实际试玩增加显式的 `--show-editor-comparison` 开关，且要求编辑器处于
`shadow` 或 `on`。服务端在最终选择完成后发送独立的
`editor_comparison` SSE 事件，内容包括初稿、候选稿、guard、选择结果和原因；
观察器自身出错只写 trace，不影响回合提交。

浏览器在每回合旁白后渲染编辑前/编辑后对照，标记最终采用项；桌面为双栏，
窄屏为单栏。对照记录保存在当前 Web 进程中，因此刷新可恢复。默认响应不含
这些开发数据，只有显式开关开启时才暴露，避免把草稿无意带入正常产品接口。

## 验证结果

- `python -m unittest discover -s tests -v`：187 个测试通过。
- `tools/validate_content.py tests/fixtures/open_neighbor_scene.yaml`：0 warning。
- mock provider 分别以 `shadow` 和 `on` 跑通 CLI 一回合并正常退出。
- 真实 DeepSeek/Kimi 的编辑质量、延迟、候选通过率和误伤情况尚未试玩验证。

## 下一步

1. 用真实 provider 跑 `shadow`，收集初稿/候选稿对照，重点观察心理运动、人物
   声音和节奏是否被误删。
2. 从对照中建立人工认可的回归集，记录“应保持原样、应局部修改、明显越界”
   三类案例；不使用通用 AI 检测分数代替判断。
3. 根据真实数据校准 65%/120% 阈值和保护词策略，再决定是否开放 `on`。
4. 若同步 `shadow` 明显拖慢回合提交，再复用后台 worker 形态异步生成候选。
