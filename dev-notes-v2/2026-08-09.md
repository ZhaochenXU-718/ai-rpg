# 2026-08-09｜故事工作室阶段 B：三个开放问题定案，M1–M3 落地

## 今日主题

准备实现故事工作室的后续阶段。盘点 2026-08-05 方案（`docs/story-studio-design.md`）
的实现进度，确认下一阶段目标是补完阶段 B——短简报概念提案与分阶段结构化
生成，让工作室从"能编辑故事"变成"能快速生成新故事"。动手前把第 15 节中
阻塞实现顺序的三个开放问题逐项定案。

## 问题与思考

### 现状盘点

阶段 A 纵向版本已落地；阶段 B 六项中已完成字段级 LLM 操作（灵感/补全/润色/
检查）、审阅账本和发布门槛雏形。仍缺三大块：短简报 → 概念提案（"从想法
开始"的入口完全缺失）、8.2 节的分阶段结构化生成管线、集中的审阅队列与上游
变更提示。批量生成落地后一次会产生大量待审阅字段，散点 chip 无法支撑审阅，
所以审阅中心必须跟在管线后面做。

### 规模模板如何确定（原开放问题 5）

讨论了"是否由 LLM 和创作者商讨确定"。结论是商讨可以有，但必须框在代码
定义的预算区间内，且发生在概念阶段一次谈清，而不是生成过程中反复协商——
否则规模变动会让已生成内容大量作废，违背"单独重试、不重做已确认阶段"的
管线原则。区间必须由代码而非 LLM 掌握，因为规模直接决定生成成本、校验预期
和游玩时长锚定，这三件事都不该由 LLM 负责。

### 发布模型（原开放问题 2）

原方案的二选一（仓库内正式文件 vs 独立内容包）是本地工具语境。今天确认
产品最终形态是托管网页平台（用户登录使用，参照 isekaizero.ai），不存在向
平台外分发内容的场景，两个原选项因此都不对：

- 可变内容文件直接服务玩家不成立——创作者持续迭代已上线故事时，一次保存
  就可能让玩家进行中的会话前后矛盾；
- 内容包的打包格式、校验和分发、安装机制都是为"内容离开系统"设计的，
  托管平台上没有服务对象。

正确形态是取内容包方案的内核（版本清单）、去掉外壳（可分发文件包）。

## 形成的结论

设计文档第 0 节新增三条已确认决定（9–11），第 15 节对应问题标记已定：

1. **模型策略（决定 9）**：最终形态为托管平台；后续提供多模型选择，创作
   模型与游玩模型分开配置；当前开发沿用 kimi 和 deepseek。实现上创作侧与
   游玩侧的 provider 边界从现在起保持可分别配置。
2. **规模模板（决定 10）**：三层机制——代码定预算区间（与
   `target_duration_minutes` 挂钩，初始数值从现有 4 个故事归纳）、概念阶段
   LLM 提出具体配置并说明理由（可偏离区间）、创作者拍板。偏离区间只触发
   创作质量提示，不是阻塞校验错误：硬约束只留给引用完整性这类机器问题，
   规模属于创作判断。
3. **发布模型（决定 11）**：不可变版本快照。四个领域概念——可变草稿、
   不可变发布快照、发布记录（版本号、源草稿 revision、审阅戳）、当前版本
   指针。回滚 = 指针指回旧快照；游玩会话绑定具体快照，创作者发布新版或
   回滚不影响进行中的会话。存储介质将来从本地文件换成数据库/对象存储，
   领域模型不变。不设计 zip 包、校验和分发等平台外分发机制。

### 阶段 B 实现计划（六个里程碑）

- **M1 存储结构整理**：`content/drafts/`（草稿）+ `content/releases/<id>/`
  （快照 + `releases.json` 发布记录与 current 指针），现有平铺故事迁移为
  草稿；发布动作执行门槛检查（无阻塞校验错误、无未审阅 LLM 内容），
  "未审阅内容不能进入可发布版本"在此落地；发布/版本列表/回滚 API。
- **M2 创作/游玩模型分开配置**：`studio.py` 单一 `--llm` 拆为创作、游玩两个
  参数，本阶段不做选择 UI。
- **M3 短简报 → 概念提案**：简报（创意 + 篇幅档位 + 题材标签）→ 2–3 个
  概念提案（方向、概述、冲突、隐藏真相方向、建议规模及理由）。提案端点
  无状态不落盘，选中才创建故事，概念内容以 `unreviewed` 写入蓝图。规模
  区间在此落地。
- **M4 分阶段生成管线**（最大块）：新模块 `server/studio_pipeline.py`，按
  8.2 节顺序编排人物 → 场景 → 分布 → 模块 → 依赖检查 → 开场。每阶段结构化
  schema + 最小上下文、代码分配 ID 与引用、生成请求绑定草稿 revision、
  单阶段可重试。UI 为生成向导，长调用走现有 SSE。8.4 节质量控制作为代码侧
  检查（禁退休 DSL、隐藏真相不泄漏进玩家文案等）。
- **M5 审阅中心与上游变更提示**：按实体分组的待审阅列表、跳转、批量确认；
  上游内容变更把下游已审阅字段降级为 `needs_review`。
- **M6 收尾**：规模偏离质量提示、生成记录落盘、文档更新、mock 下"简报 →
  可玩草稿 → 发布"全流程集成测试（覆盖 MVP 验收条件 1 和 4）。

M1/M2 是基础先行；M3→M4→M5 构成纵向路径，每个里程碑结束时工作室处于
可用状态。

- **目录迁移**：`content/` 平铺故事迁入 `content/drafts/`；pre-pivot 历史

  游玩"的流程已失效）。`.studio/` 审阅账本位置不变。
- **发布层**（`studio_service.py`）：`publish` 在锁内做 revision 校验 +
  双门槛检查（零阻塞校验错误、零未审阅 LLM 字段），从草稿深拷贝生成快照

  revision、统计）并推进 current 指针。版本号系统递增（1.0.0 → 1.1.0，
  创作者不管理版本号）。`rollback` 只改 current 指针；快照文件存在即拒绝
  覆盖。损坏的 releases.json 显式报错而不是静默清空——否则版本号会从头
  计数并试图覆盖不可变快照。
- **故事发现**（`cli.py`）：已发布故事优先返回 current 指向的快照，未发布
  故事回退草稿，按故事 ID 去重；templates/ 与 archive/ 不参与发现；兼容
  平铺 YAML 的普通目录（测试 fixtures 依赖此行为）。
- **API**（`studio.py`）：GET `releases`、POST `publish`（201）、POST
  `rollback`。
- **UI**（`studio.html`）：顶栏"发布"按钮 + 发布与版本对话框（门槛状态、
  版本列表、当前版本标记、回滚按钮）；故事库条目显示"已发布 vX.Y.Z"。
  发布成功后按钮保持禁用直到重新打开对话框，防止误发两个相同版本。
- **测试**：`test_story_studio.py` 新增 6 个发布层用例（快照不可变、双门
  槛、revision 冲突、版本递增与回滚、故事库发布版本）；
  `test_content_independence.py` 新增"发布快照优先于草稿"发现用例；

## 字段合并：公开身份并入公开形象

用户反馈玩家角色页的"公开身份"（`player_role.public_identity`）与"人物
公开形象"（`characters.player.public_profile`）造成强烈的重复性困惑。
排查后确认合并成立，且方向唯一：

- `public_profile` 被引擎真实消费（`perception.py` 玩家感知实体描述、
  `renderer.py` 在场人物列表）；
- `public_identity` 没有任何引擎代码读取——只有校验器要求非空。
  `player_role` 中真正被运行时消费的只有 `constraints`（旁白/提案/
  iron_laws 三处）和 `id`。竞品能力分析文档早已记录该断层；
- 旁白的作者私有上下文**明确跳过玩家人物卡**（`build_author_context`
  中 `character_id == story.player_id` 即 continue），所以玩家卡私有
  字段也不是"真实身世"的运行时归宿——每回合进旁白的只有 `ai_plot`；
- 实证：用户新草稿（灰烬里的名字）把"公开身份"填成了真实身世（孤儿院
  长大）、"公开形象"填成伪装身份（假扮方家女儿）——字段命名本身在诱导
  误用，而填进去的真实身世实际上哪儿都不去。

实施：`player_role` 必填字段改为 `name` + `private_goal`；残留
`public_identity` 触发校验警告（不是错误）；`_blank_story` 与工作室
玩家角色页移除该字段，"公开形象"帮助文字明确"进入玩家感知与人物列表；
不愿示人的身世写进故事蓝图（如隐藏真相）"。存量内容迁移：霍格沃茨与
灰烬里的名字直接删除（信息已被 premise/ai_plot 覆盖）；尘缘把"初入
青山弟子"这一事实合入公开形象后删除；测试夹具与模板同步；两份审阅
账本中的残留字段条目清除。`private_goal` 与 `ai_plot` 的"作者写了但
旁白读不到"缺口仍在（模板注释已标注"长线看会并入 ai_plot.player_role"），
留待生成管线阶段一并处理。

验证：218 个测试通过；霍格沃茨与尘缘校验 0 警告；浏览器确认玩家角色页
为姓名/公开形象/私人目标三字段。注意：正在运行的工作室进程需重启才能
加载新校验器，否则会对迁移后的草稿误报 public_identity 缺失。
