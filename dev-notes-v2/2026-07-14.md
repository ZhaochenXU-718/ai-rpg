# 2026-07-14 开发记录：叙事优先转向与老代码处置方案

## 今日主题

在 `pivot/narrative-first` 分支正式转向叙事优先架构：重点实现**导演、记忆、NPC agent** 三大模块，机械判定收缩到铁律清单，前验路由改为后验校验。本篇是转向的论证记录和**老代码删减重构方案**——按约定，拆除方案先行，新模块随后。

## 问题与思考

### 转向的直接证据

pre-pivot 架构（前验路由：行动 → 意图/能力映射 → 机械裁决 → 才允许叙事）在 2026-07-14 的真实 DeepSeek 试玩（trace `6b1d1052bbcc`）中暴露的问题：

1. **叙事核心事实无处安放**：周师傅"明天下午来取帆布"、林姐"家里有块桌布"——承诺、人情、局势这类推动剧情的事实既不是数值也不是物品转移，机械能力层接不住，成为幻影承诺，玩家连续两回合追逐不存在的东西（无效回合率 50%）。
2. **数值软状态制造疏离感**：`neighbor_lin.rapport 1→2` 这样的回执在提醒玩家"你在操作 Excel"，而 rapport 数值实际不驱动任何东西。
3. **每小时游玩需要一层新机械能力**：`social.request_item` 只覆盖"借物品"一个动词；对话、帮忙、答应、赴约……逐个建模的启动成本压垮了核心体验验证。
4. **prompt 规则挡不住模型**：Director prompt 明文禁止在节拍里发明物品和承诺，模型违反了两次。结论：**只有代码级校验算控制，prompt 只是缓解**。

### 什么必须保住

转向不是转向 ISEKAI ZERO 式纯 Chat：幻影桌布**没有进入状态**正是账本的功劳。差异化底线收缩但不放弃：

- **铁律清单**（authoring-contract 核心 Canon 栏的运行时化）：人物生死与在场、关键物品所有权、秘密披露、锚点进度、不可逆事件、世界边界；
- **原子提交、revision、checkpoint / 分支、trace、感知墙**——全部保留；
- 对玩家的承诺从"看到的都是真的"调整为"**重要的事都是真的**"，这是后验校验的诚实代价。

### 新循环

```text
输入 → Director 编排 → NPC agent 接话 → 叙事生成（散文即产品）
→ 事实抽取（结构化：移动 / 获得 / 披露 / 承诺 / 兑现）
→ 铁律校验（代码检查；冲突则重生成，有上限）
→ 原子提交：铁律事实进账本，情节进叙事记忆，新实体进注册表
→ 锚点 storylet 订阅事实，兑现创作者承诺
```

试玩的 tease-loop 是新架构的第一个验收用例：**帆布承诺必须成为承诺清单里的事实，被后续兑现或明确爽约**。

## 形成的结论：老代码处置清单

原则：**拆除与新建分开提交**；每个批次结束仓库必须可玩、测试全绿；删除即删除（git 历史即归档），不留死代码。

### 风险与对策

- **后验校验漏网**：矛盾先发生后拦截，偶尔会漏 → 每次抽取与校验全量进 trace；重生成有上限；漏网违规必须可事后定位。
- **抽取成本**：事实抽取可能增加一次 LLM 调用 → *假设*：叙事与结构化抽取合并为同次调用的双通道输出，Phase 2 验证。
- **中间态不可用**：拆除面大 → 每批次结束必须可玩 + 全绿，禁止跨批次留断头。
- **回放确定性减弱**：散文不参与回放承诺；事实批次提交仍走 revision / checkpoint，账本层回放保持确定。
