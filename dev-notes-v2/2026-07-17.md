# 2026-07-17｜P0：让作者意图进入叙事闭环；P1：软模块与多开场

## 背景

[Creator's Guides 能力分析](../docs/isekaizero-creators-guides-capability-analysis.md)确认了当前最大断层：schema 强制作者填写 `motivation`、`voice`、`initial_relationship`，但这些字段只进 `audience=NPC` 的 `subject_context`，而当前没有自动 NPC 回合——作者字段通过校验却不参与主要生成。`premise` 只用于开场渲染，`private_goal` 在运行时完全无消费方。

## 本批次落地

### 内容 schema：作者叙事分层

- 新增可选顶层字段：`player_facing_summary`（只给玩家）、`emotional_contract`、`ai_plot`（五个固定键，含 `hidden_truth`）、`narrative_guidelines`、`critical_reminders`（最多 4 条）；
- 人物卡新增可选：`secret`（正式校验）、`pressure`、`behavior`、`mannerisms`、`narration_notes`、`dialogue_examples`；
- `ai_plot` 键名封闭：拼错 `hidden_truth` 会被校验器拒绝，防止本应保密的内容因笔误流入提案。

### NarrativeAuthorContext：旁白专用作者通道

- 新增与 `PerceptionSnapshot` 分离的 `NarrativeAuthorContext`（`story_brief` / `emotional_contract` / `active_guidelines` / `critical_reminders` / `in_scene_character_cards`）；
- `narration` 每回合按当前可见人物编译在场人物完整私有卡，随 `NarrativeRequest` 交给旁白，并记入 trace；
- 旁白系统 prompt 从"不使用未披露私密信息"改为"知道但不得说破"：秘密可以驱动回避、迟疑和撒谎，但玩家未探明前不得写成已知事实；`critical_reminders` 声明为最高优先级；
- prompt 版本：narrate v6→v7，suggestions v3→v4。

### ideas：脱敏故事方向

- 提案请求新增 `story_direction`：`ai_plot` 去掉 `hidden_truth`，加 `emotional_contract`；
- 人物卡私有字段（含 `pressure`）刻意不进提案：卡片文本原样展示给玩家，没有披露守卫——这是对分析文档 P0 第 4 条"当前压力"的一处有意收窄，等真实试玩证明提案确实缺方向再放开；
- 既有隐藏实体过滤器继续兜底：脱敏蓝图若提到玩家未见过的作者实体，引用它们的草稿仍被丢弃。

### prompt 快照测试

新增 `tests/test_prompt_routing.py`，用夹具中每层唯一的哨兵串断言路由：

| 作者层 | 旁白 | 提案 | 玩家感知 | 事实抽取 |
|---|---|---|---|---|
| `ai_plot`（含 hidden_truth） | ✓ | 去 hidden_truth | ✗ | ✗ |
| `emotional_contract` | ✓ | ✓ | ✗ | ✗ |
| guidelines / reminders | ✓ | ✗ | ✗ | ✗ |
| 在场人物私有卡 | ✓ | ✗ | ✗ | ✗ |
| `player_facing_summary` | ✗ | ✗ | ✗ | ✗ |

这类"字段进入了哪个调用"的断言正是 `private_goal` 空转问题应有的验收工具。

## P1（同日落地）：软模块、编排器与多开场

### modules schema

- 可选顶层 `modules`：`category`（功能五类枚举：main/character/pressure/aftermath/side）、`title/purpose/hook/trigger` 必填，`involves/escalation/resolution/fallback/repeatable/cooldown_turns/min_turn/priority/tags/requires` 可选；
- 类别按叙事功能划分而非题材（引擎必须故事无关），题材化分类用自由 `tags`；
- 模块禁止 `effects/when/state_patch/conditions`——与被拆掉的旧 storylet 的本质区别；
- `requires` 引用其他模块的软状态（如 aftermath 依赖某模块 `dropped`），是"选择有后果"的轻量实现。

### 编排器（`server/engine/modules.py`）

- 纯确定性代码，无 LLM 调用、无状态权限：资格过滤（状态、冷却、`min_turn`、在场实体交集、requires）→ 排序（priority → 类别 rank → 最少抛出 → 最久未抛）→ 配额（至多 3 个，main 可用时保底一席）；
- `CategoryPolicy` 注册表是扩展点：新增类别 = 注册表加一条 + 校验器镜像常量（有测试保证两者一致）；
- 自然语言 `trigger` 编排器不解析，原样交给旁白判断——代码守可判定的账，模型处理语义；
- 选择是纯函数：旁白组 prompt 与提交后标记可确定性重算同一批候选。

### 生命周期（软状态，随分支恢复）

- `ModuleRecord` 存于 `MemoryState.module_states`，undo/branch 自动回滚；
- 提交成功的回合把候选记 `offered`；被忽略 3 次自动消退 `dropped`；
- M2 小结输出 `module_updates` 标注 `engaged/resolved/dropped`，代码校验转移（`resolved` 终态；`dropped` 可被晚接的钩子复活为 `engaged`）；压缩器目录只含已浮出水面的模块，未出现的素材不泄入小结；
- 候选只进旁白（作者私有上下文），不进提案、玩家感知与事实抽取（有路由测试）；模块状态经 `memory` 命令可见，trace 记录候选与状态变化。

### 多开场

- 可选顶层 `openings`：`title` + 可选 `intro` + `positions` 覆盖；只改初始位置，进入游戏后同一管线；CLI `--opening <id>`。

### prompt 版本

narrate v8（候选模块使用规则：贴合才编织、一回合至多推进一个、忽略过的钩子换轻方式或不提）；memory-compaction v2（`module_updates` 字段与标注纪律）。

### 验收

- 全量 123 个离线测试通过（P1 新增 19 个：选择、冷却、消退、转移、requires、路由、开场、校验）；
- 夹具含三个示例模块（main/character/aftermath + requires + tags）与两个开场，通过校验器；
- CLI 冒烟：提交回合后 `memory` 显示模块 offered 状态；`--opening courtyard_start` 正确落位并打印引导文字。
