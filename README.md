# AIRPG — 叙事优先的 LLM 原生互动叙事引擎

一句话：**导演推动剧情，NPC 扮演人物，记忆维持世界，铁律守住底线——其余一切交给语言。**

本文档描述项目的**终局形态**，为后续实现指明方向。它是活文档：每次里程碑复盘时都应审视一遍——修正不合理之处、补充当时未察觉的必要模块、替换更好的方案（见文末[修订约定](#修订约定)）。

三条不可动摇的底线（2026-07-14 转向后修订，历次沉淀见 [engine-principles](docs/engine-principles.md)）：

1. **不做某个故事或某个类型的专用引擎**——引擎代码不认识故事专名，词汇全部属于内容。
2. **LLM 不是文字润色器**——理解、导演、扮演、创造全部由它承担；散文本身就是产品。
3. **铁律不交给 LLM**——生死、在场、关键物品、秘密披露、锚点进度和世界边界由确定性账本守护；LLM 生成的情节触碰铁律时，必须通过校验才能成为事实。

## 为什么转向（2026-07-14）

原架构是**前验路由**：玩家行动先映射到意图和能力模块，机械裁决通过后才允许产生叙事。两个样板故事和真实试玩证明了它的问题：

- 玩家获得的是表达自由而非影响自由——结果空间被作者预写面和能力覆盖面封闭；
- 数值软状态（rapport 之类）与逐回合机械回执不断提醒玩家"你在操作规则引擎"；
- 叙事真正的核心事实——承诺、人情、局势、剧情推进——恰恰无法被机械能力承载（试玩中"周师傅答应明天给帆布"成为无处安放的幻影承诺，就是直接证据）；
- 每支持一小时游玩就需要一层新的机械能力，启动成本压垮了核心体验的验证。

转向为**后验校验**：先让 Director 和 NPC 自由生成情节，再从散文中抽取结构化事实、校验铁律、原子提交。控制的时机从"行动前"移到"事实提交前"，控制的粒度从"每个数值"收缩到"铁律清单"。**铁律检查必须是代码对结构化抽取的检查，不能是 prompt 训诫**——试玩已两次证明 prompt 规则挡不住模型。

论证过程与老代码处置方案见 [dev-notes-v2/2026-07-14.md](dev-notes-v2/2026-07-14.md)；产品层依据见 [competitive-analysis-isekai-zero](docs/competitive-analysis-isekai-zero.md)。pre-pivot 架构完整保留在 `feat/perception-wall-and-capability-router` 分支（至 commit `4b11f0b`）。

## 目标循环

```text
玩家自由输入（或采用一张 LLM 提案卡）
→ Director 读锚点、节奏与记忆，编排本回合：场景走向 + 哪些 NPC 参与
→ NPC agent 按动机、私有记忆与承诺清单接话、行动
→ 生成本回合叙事（散文即产品）
→ 事实抽取：从叙事中抽出结构化事实变化（移动、获得、披露、承诺、兑现）
→ 铁律校验：与账本冲突则重新生成；不冲突则原子提交
→ 记忆更新：铁律事实进账本，情节进叙事记忆，新实体进注册表
→ 锚点 storylet 订阅新事实，兑现创作者的关键剧情承诺
→ 玩家继续、撤回修改或从提交点创建分支
```

## 三大核心模块

| 模块 | 职责 | 关键内容 |
|---|---|---|
| **导演** | 让剧情沿创作者锚点自然前进 | 节奏与张力控制、场景编排、NPC 调度、锚点兑现时机、生成预算 |
| **记忆** | 让世界记得一切重要的事 | 铁律账本、实体注册表（Local Canon）、承诺清单、Chapter / Arc 叙事摘要 |
| **NPC agent** | 人物真实感 | 动机、秘密、说话方式、私有记忆、关系的定性事实（不再是数值） |

支撑设施（自 pre-pivot 架构保留）：**感知墙**（决定每个 prompt 能看到什么——玩家看什么、每个 NPC 知道什么、Director 可用什么）、**状态时间线**（checkpoint / 撤回 / 分支）、**trace**（每次生成、抽取、校验、提交可审计）、**内容校验器**。

## 铁律清单（唯一的机械判定面）

- 人物生死与在场位置（场景粒度）；
- 关键物品的存在与所有权；
- 秘密是否已向玩家披露；
- 剧情锚点的触发与顺序；
- 已提交的不可逆事件；
- 创作者声明的世界边界（绝不可能发生的事）。

其余一切——情绪、关系冷暖、普通对话、环境细节、小事件——都是叙事，由记忆而非数值承载。类型差异（悬疑 / 都市 / 修仙）表达为 Director 政策与铁律扩展的选装，而不是另一套机械引擎；需要严格资源与检定的硬核模式，是未来在此之上的可选收紧。

## 玩家如何与系统交互

只有两种输入：**自然语言**，或**采用一张 LLM 提案卡**。没有意图菜单、没有对象 ID、没有默认报价、没有数值回执。

1. **自由表达**："我假装醉酒撞翻酒盘，趁乱溜向侧梯。"不需要任何系统词汇；提案卡只是灵感，不是白名单。
2. **结果就是散文**：只有铁律事实变化时附一行回执（"防雨布现在在你手上"）——回执是账本的承诺，不是数值报表。
3. **接不住就明说**：理解失败、澄清、重生成都不消耗任何东西。
4. **可撤回的权威状态**：撤回恢复父提交并创建新分支，历史完整保留。协议见 [state-timeline](docs/state-timeline.md)。

对玩家的三条承诺：**重要的事都是真的**（铁律事实从不出错、承诺必被记住）、**没接住不收费**、**不满意可以回到分岔点**。

## 故事创作者如何与系统交互

创作者仍是**声明世界的立法者**（[authoring-contract](docs/authoring-contract.md) 继续有效，判定面按转向收缩）。提交：

1. **世界法则与边界**：什么绝不可能发生；尺度、风格与禁区。
2. **人物卡**：身份、动机、秘密、说话方式、初始关系（定性描述）——NPC agent 的全部人格来源。重要人物属于 Core Canon，LLM 只能调度不能临场创造。
3. **关键物品与空间图**：进入铁律账本的最小集合。
4. **剧情锚点与结局**：storylet 只订阅事实、兑现关键因果；锚点之间全部即兴。
5. **感知与披露**：谁知道什么秘密、玩家何时能知道。
6. **生成预算**：允许 LLM 扩建哪些类型的局部世界（Local Canon 原型与预算）。

不再提交：意图菜单、数值白名单（`resolution_limits`）、物品请求策略、普通行动 storylet、逐意图报价配置。

## 现状对照（2026-07-14 转向起点）

**继承自 pre-pivot 分支的可复用资产**：确定性账本与原子提交、感知墙、内存 checkpoint / 撤回 / 状态分支、trace、提案卡（`ideas` / `idea <n>`）、Local Canon 准入（原型 / 预算 / 命名 / 冲突检查）、DirectorBeat 骨架、内容校验器、DeepSeek / mock provider 层、开放场景夹具。

**待拆除**：报价与逐意图风险配置、静态能力路由、`resolution_limits` 数值裁剪、`social.request_item`、数值软状态、意图协议面（ActionPlan 路由语义）。完整的保留 / 改造 / 拆除清单见 [dev-notes-v2/2026-07-14.md](dev-notes-v2/2026-07-14.md)。

**演进顺序**：

1. **拆除机械判定面**：按处置清单删除报价 / 数值裁剪 / 能力路由 / 请求策略 / 意图面，CLI 收敛为自然语言 + 提案卡，样板故事重定基线，全量测试保持绿色；
2. **铁律账本 + 后验校验最小循环**：事实抽取协议 + 代码级冲突检查 + 重生成上限，在开放夹具上跑通；
3. **Director v2**：每回合场景编排与锚点推进（替代保守的节拍调度员）；
4. **NPC agent**：动机 + 私有记忆 + 承诺清单——验收用例：试玩中"周师傅的帆布承诺"必须被兑现或明确爽约；
5. **Chapter 摘要与长篇试玩**：叙事记忆分层，跑第一个多小时故事；
6. **重评控制收紧**：根据长篇试玩证据决定悬疑 / 硬核选装需要哪些机械模块回归。

## 快速开始

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 游玩（LLM 模式需要 DEEPSEEK_API_KEY；输入自然语言，或 ideas / idea <n> 使用提案卡）
python server/cli.py --llm deepseek   # 未指定故事时从 content 目录选择
python server/cli.py content/rooftop_supper.yaml --llm deepseek
# 校验内容
python tools/validate_content.py content/rooftop_supper.yaml
# 测试
python -m pytest tests/ -q
```

> 注：仓库当前处于转向的第 1 阶段（拆除机械判定面）之前，运行时仍是 pre-pivot 管线；上述命令均可用，但报价、意图等机械面将按处置清单逐步移除。
