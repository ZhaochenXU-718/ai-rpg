# AIRPG 作者主权与生成边界契约

日期：2026-07-14
状态：v0.1，作为开放行动阶段的目标契约

## 1. 目的

AIRPG 的创作者是世界的立法者，不是枚举所有合法互动的分支程序员。本契约规定作者、确定性引擎、LLM 与表现层分别拥有什么权限，并作为内容 schema、能力模块、Director 和 Local Canon 的共同上位约束。

核心原则：

> 强规则保护世界一致性，不负责限制故事只能沿作者预先踩出的脚印前进。

## 2. 不可动摇的边界

1. LLM 不直接修改权威状态；所有持久变化必须结构化、验证并原子提交。
2. 引擎代码不认识故事专名；人物、地点、物品、动机和世界词汇全部来自内容。
3. 已提交事实、秘密披露、资源、位置、物品和不可逆主线变化受强控制。
4. Storylet 是因果锚点和状态订阅者，不是普通行动能否产生结果的白名单。
5. 重要人物由作者定义；LLM Director 可以调度既有人物进场、反应和推进计划，但不能临场创建新的核心人物。
6. 玩家自由输入与 LLM 行动提案地位相同；机械 intent、对象 ID 和能力工具属于内部协议，不是最终玩家界面。

## 3. 权限归属

| 归属 | 必须负责的内容 | 不应负责的内容 |
|---|---|---|
| 作者 | 世界法则、核心事实、主要人物及其动机 / 秘密、初始状态、剧情锚点、结局条件、尺度与禁区、能力模块参数 | 枚举每个问题的所有解法、普通对话逐句回应、所有人物出场时机 |
| 能力模块 | 行动前置条件、成本、检定、不确定性档位、资源 / 物品 / 位置账本、机械回执 | 创造世界法则、改写核心秘密、替作者写剧情分支 |
| LLM 理解 / 规划 | 从自由文本识别目标、手段、对象和期望，生成或修订结构化计划 | 宣布成功、绕过能力权限、直接写状态 |
| LLM Director | 基于已有人物动机、位置、日程和局势提出反应与下一幕节拍 | 凭空创建重要人物、改变作者秘密、跳过世界边界 |
| LLM 渲染 | 根据已提交事实写叙事；生成不影响玩法的表现细节 | 把尝试写成成功、让未提交事实影响后续玩法 |

## 4. 事实权限层

| 层级 | 示例 | 产生与提交方式 |
|---|---|---|
| Presentation | 天气质感、杯子颜色、路人的一句闲话 | LLM 可自由表达，不持久化，不影响玩法 |
| Local Canon | 局部地点、临时局势、次要承诺；后续可选次要 NPC 晋升 | LLM / Director 提议，经过原型、预算、生命周期和冲突检查后提交 |
| Mechanical | 位置、物品归属、资源、HP、关系数值、检定结果 | 能力模块裁决并提交 |
| Core Canon | 世界法则、谜底、重要人物身份与秘密、不可逆主线事实 | 作者或严格锚点控制 |

Local Canon 不是“允许 LLM 任意写世界”。第一版优先支持局部地点和局势；重要人物禁止临场生成，无名路人保持在表现层，次要 NPC 只有在玩家持续互动且确有持久化价值时才考虑晋升。

## 5. 未预写行动的替代政策

旧政策“未命中 storylet 就消耗时间、只产生白名单软代价、Canon 不动”废止为目标规则。新规则区分三类情况：

1. **违反硬边界或信息不足**：明确解释或澄清，零成本，不推进世界。
2. **世界内合理但尚无能力模块支持**：明确报告能力缺口，零成本；不得用无关 soft patch 冒充部分成功。
3. **已有通用能力支持**：能力模块独立判断可行性、成本和不确定性，允许提交经过验证的 Mechanical 结果；是否存在 action storylet 不参与普通行动授权。

Storylet 在能力结果提交后读取新状态并兑现关键剧情锚点。例如“进入档案室”可以由钥匙、交涉、撬锁或其他能力达成；storylet 只负责玩家确实进入后触发核心发现。

## 6. 默认玩家交互

默认模式是自由叙事：无全局倒计时、可逆行动自动执行、结果后展示机械回执，并允许从提交点撤回或创建分支。

```text
自由输入 / 选择 LLM 行动提案
→ LLM 生成 ActionPlan
→ 能力模块验证和裁决
→ 可逆结果自动原子提交
→ Storylet / Director 响应已提交状态
→ 叙事 + 机械回执
→ 继续 / 撤回修改 / 创建分支
```

只有死亡、永久伤残、关键关系永久破裂、唯一物品消耗和不可逆主线转折等结果需要完整事前确认。澄清、理解失败、重规划、查看状态、重新生成叙事、放弃方案和切换分支永远不推进世界时间。

## 7. 时间与压力

必须区分：

- `turn_no`：分支内的世界步与叙事序号，不是玩家资源；跨分支的全局先后由单调 `state_revision` 与日志时间确定；
- 世界时间：昼夜、日程、旅行和 NPC 行动的模拟能力；
- 倒计时：悬疑挑战或硬核故事可选的压力模块，默认关闭。

即使启用倒计时，也由具体能力判断行动是否真正耗时，禁止给所有有效回合统一附加时间损失。

## 8. 行动提案与 Director Beat

LLM 可以基于 `PlayerPerception`、当前目标、近期事件和可用工具生成 3—5 张行动提案。每张提案必须先转成结构化计划并在当前 state revision 上通过验证；玩家直接选择时执行被冻结的已验证计划，编辑后才重新规划。

Director Beat 可以调度作者预定义的角色和事件。例如“某位既有角色进入当前场景”必须引用已有 `character_id`，并验证位置、可达路径、动机与日程。只有需要创建状态中不存在的持久局部事实时，才进入 Local Canon 审核。

提案卡只描述玩家将尝试什么，不保证尚未裁决的结果，不读取感知墙后的秘密。自由输入始终保留，提案是灵感而不是行为白名单。

## 9. 撤回与分支

重新生成叙事只重写同一个 `CommittedOutcome`，不改变状态；撤回行动恢复父提交的完整快照并创建新分支；重新检定是否允许使用新随机结果属于玩法政策。

每个提交节点至少关联父提交、权威状态、storylet 消耗、临时效果、近期事件、叙事记忆和随机源状态。切换或恢复节点后必须产生新的单调递增 revision，旧报价和验证结果立即失效。

最小运行时协议与当前实现边界见 [state-timeline.md](state-timeline.md)。

## 10. 验收标准

开放行动阶段至少满足：

- 没有作者 action storylet 时，通用能力仍能产生可信、持久、可回放的结果；
- 结果回执能区分能力结果、固定成本、storylet 和 world rule；
- 主目标未达成时不得仅凭无关 soft patch 标记为部分成功；
- 低风险自由文本行动不要求完整报价；
- 重要人物只来自作者角色池，Director 只做受约束调度；
- 相同事件日志可恢复相同权威状态。
