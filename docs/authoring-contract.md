# AIRPG 作者契约

## 作者提供什么

- 故事前提、风格与软边界；
- 玩家文案与 AI 蓝图分层：`player_facing_summary` 只给玩家看，`ai_plot`（含 `hidden_truth`）、`narrative_guidelines`、`critical_reminders` 和 `emotional_contract` 是给模型的指令；
- 玩家身份与表达约束；
- 人物卡：公开形象、动机、口吻、初始关系，可选秘密、压力、行为模式、习惯动作、旁白说明和示例对白；
- 场景：名称、目的、当前目标、入口文字、静态环境对象和出口；
- 可选剧情模块：分类、钩子、触发语义、升级与消退方向，不含任何状态效果；
- 可选多开场：标题、引导文字和初始位置覆盖；
- 进入物理账本的关键物品；
- 所有人物与关键物品的初始位置。

作者不需要预写普通行动、人物是否答应、关系数值、剧情旗标、锚点触发、自动结局或动态生成预算。

## 权限边界

| 主体 | 可以 | 不可以 |
|---|---|---|
| 作者内容 | 定义人物、场景、关键物品、剧情模块和软叙事边界 | 用 flags/storylet 枚举普通剧情 |
| 剧情模块 | 提供钩子、触发语义和升级方向 | 携带 effects 或修改任何状态 |
| 模块编排器（代码） | 按冷却、在场与依赖筛选候选 | 评估触发语义、强制触发或改写结果 |
| 旁白 provider | 续写散文与人物回应，可选编织候选钩子 | 直接修改权威状态、强推模块 |
| 提案 provider | 给玩家可编辑灵感 | 替玩家或 NPC 决定结果 |
| 抽取 provider | 提出人物移动与关键物品转手 | 输出任意状态 patch |
| 代码 | 维护位置、归属、revision 与时间线 | 判断人物感情、承诺意义或故事完成度 |

`global_rules.boundaries` 和人物卡进入 prompt，属于创作约束，不自动升级为代码铁律。

作者私有材料走独立通道：故事蓝图与在场人物卡编译成旁白专用的作者私有上下文，旁白"知道秘密但不得无条件披露"；行动提案只拿到去掉 `hidden_truth` 的脱敏故事方向；玩家感知和事实抽取完全看不到这些字段。哪个字段进入哪个调用由 prompt 快照测试固定。

## 何时新增关键物品

只有当物品的连续归属对后续故事确实重要时才进入 `items`。普通杯子、食物细节、临时纸条和装饰不应为了“可能有用”全部建模。

## 何时新增硬规则

需要同时满足：跨故事复现、记忆与小结仍会失败、错误代价明确、可写成故事无关检查、测试收益高于维护成本。否则保持在叙事层。
