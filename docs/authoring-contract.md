# AIRPG 作者主权与生成边界契约

日期：2026-07-15
状态：v0.3，Phase 2 最小后验闭环

## 1. 契约目标

AIRPG 的作者是世界的立法者，不是枚举所有合法互动的分支程序员。作者声明什么必须真实、谁是重要人物、哪些事实不可越过，以及关键剧情最终要兑现什么；LLM 负责在这些边界之间导演、扮演和写作。

> 强规则保护事实一致性，不负责把故事限制在作者预先写好的行动路线里。

## 2. 不可动摇的边界

1. LLM 不直接修改权威状态。散文、行动卡、DirectorPlan 和 NpcTurn 都不是事实。
2. 持久变化必须先被抽取为 `FactBatch`，经过代码级铁律检查，再原子提交。
3. 引擎代码不认识故事专名。人物、地点、物品、秘密、动机、禁区和语气全部来自内容。
4. Storylet 只订阅已提交事实并兑现剧情锚点，不授权普通行动。
5. 重要人物只能由作者定义。Director 可以调度既有人物；Local Canon v1 不能创建人物。
6. 玩家只有自然语言和可编辑行动提案两种等价入口，不接触对象 ID、意图菜单或能力工具。
7. 感知按主体隔离。玩家、NPC 与 Director 各自只能读取属于自己的 `PerceptionSnapshot`。

## 3. 权限归属

| 角色 | 负责 | 不得负责 |
|---|---|---|
| 作者 | 世界边界、核心人物卡、关键物品、空间图、初始铁律、秘密、剧情锚点、结局、风格、生成预算 | 枚举所有普通对话与行动解法 |
| LLM 候选叙事 | 根据作用域内事实写本回合候选散文，明确表达成功、失败和可见人物回应 | 直接写状态、使用隐藏信息、绕过后验检查 |
| LLM Director | 提议既有人物节拍与声明范围内的 Local Canon | 创建重要人物、改物品归属、披露秘密、替 NPC 作承诺 |
| 未来 NPC agent | 按人物卡、私有感知和记忆生成对白与行动提议 | 直接写状态或绕过事实抽取 |
| 确定性引擎 | 感知过滤、铁律校验、Local Canon 准入、锚点扫描、原子提交、时间线 | 猜测玩家意图、创作人物对白、硬编码故事词汇 |

## 4. 三类事实

### 4.1 表现事实

光线、气味、无后续影响的小动作等可以只存在于当前散文。只要玩家继续追问、后续回合需要记住，或它开始影响玩法，就必须晋升为结构化事实。

### 4.2 铁律事实

默认铁律域：

- 人物生死与场景位置；
- 关键物品的存在与归属；
- 秘密是否向某个主体披露；
- 人物承诺及兑现状态；
- 锚点顺序与不可逆事件；
- 作者声明的世界边界。

模型只能提出这些变化。当前检查器返回结构化 `IronLawViolation`，冲突时有限重生成，不能把 prompt 训诫当校验。

### 4.3 Local Canon

Local Canon 是经过作者预授权的局部扩建。v1 只支持：

- 挂在作者地点下的生成地点；
- 有限生命周期的局部局势。

每条提议必须通过原型、预算、`gen_` 命名空间、父地点、生命周期和重名冲突检查。预算按分支累计创建数计算，过期不释放。无 `generation` 声明即禁止生成。

## 5. 默认回合

```text
玩家自由输入 / 采用可编辑行动卡
→ Director 与未来 NPC agent 编排、扮演
→ 生成本回合散文
→ 抽取 FactBatch
→ 代码检查铁律；冲突则有限重生成
→ 原子提交事实
→ 扫描 after_world 锚点、Local Canon 生命周期与结局
→ 写入 checkpoint、记忆与 trace
→ 玩家继续、撤回或从旧节点建立分支
```

Phase 2 最小闭环已经接入 CLI。provider 返回的 `FactExtraction` 不能携带 patch；检查器只把通过在场、相邻、归属、披露者和承诺状态检查的事实转换为 `FactBatch`。一批中任何冲突都会触发至多一次候选重写，最终失败不产生回合或状态变化。

在 NPC agent 接入前，候选叙事 provider 可以临时生成在场 NPC 的可见回应与明确承诺，检查器只接受双方同场且关联实体可见的承诺。人物动机一致性仍属于生成质量问题；Phase 4 会把这部分决定权移交 NPC 自己的私有感知与人物卡。

## 6. 人物卡与多主体感知

每个非玩家核心人物必须至少声明：

- `motivation`：当前真正想维护或推动什么；
- `voice`：如何说话和表达分寸；
- `initial_relationship`：与玩家的定性初始关系；
- 可选 `secret`：不能进入玩家感知，除非披露事实已提交。

`PerceptionSnapshot` 统一描述玩家、NPC 和 Director 的作用域，但不统一它们知道的内容。玩家快照不含人物秘密；NPC 快照可以包含自己的私有人物上下文与专属记忆；任何 provider 都不能自行读取完整 state。

## 7. 锚点与结局

叙事优先 storylet 必须是 `phase: after_world`、`attribution: world_beat` 的事实订阅者。它可以在条件满足后设置 Canon flag、推进世界状态、移动既有实体或物品、增加事实并给出叙事提示。

锚点不得使用 `intent`、`intent_any`、`object_any` 或 `object_all` 路由玩家行动。锚点条件只能读取已提交状态；普通行动即使没有任何 storylet，也必须能够在未来的通用事实循环中产生可信结果。

## 8. 撤回与分支

每次成功提交产生 checkpoint。撤回恢复父节点的 state、已消费锚点、结局、近期叙事与随机源，然后创建新分支；旧历史不删除。`state_revision` 永不回退，因此旧 `FactBatch`、提案卡和 provider 响应不能跨恢复点提交。

详见 [state-timeline.md](state-timeline.md)。

## 9. 作者不再提交的内容

- `intents`；
- `resolution_limits`；
- `quote_warnings`；
- `world_rules` 自动移动；
- `items.*.request_policy`；
- `scenes.*.suggested_intents`；
- 普通行动 storylet；
- 结构化 intent/object walkthrough。

完整字段见 [content-schema.md](content-schema.md)，运行时协议见 [narrative-first-protocol.md](narrative-first-protocol.md)。

## 10. 验收不变量

- 没有普通 storylet 时，自由输入仍是正式玩家入口；
- 未提交的移动、物品、披露和承诺不能进入后续事实；
- extractor 不能返回任意状态路径，证据必须逐字来自候选散文；
- 玩家感知不能包含其他主体的秘密或远处位置；
- Director 只能调度作者人物，且进场必须通过位置与邻接复验；
- Local Canon 离开原型或预算时状态零变化；
- 任意提交失败都不增加回合、不改变 revision、不产生 checkpoint；
- 相同 checkpoint 能恢复相同权威状态。
