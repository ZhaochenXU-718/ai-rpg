# AIRPG 引擎守则

最近修订：2026-07-16，记忆 M3

## 修改问题的顺序

1. 先判断是否能用人物卡、场景文字、记忆或小结解决。
2. 再判断问题是否跨故事稳定复现，并且确实造成事实矛盾。
3. 只有这两项都成立，才考虑新增确定性状态或校验。

“以后可能用到”不足以让一个概念进入默认核心。新增硬机制必须带着长篇试玩中的失败样本、清楚的收益和可删除边界。

## 当前七条规则

1. **散文是产品。** 对话、情绪、关系、约定与局势首先是叙事和记忆问题。
2. **权威面保持最小。** 默认只守人物位置与关键物品归属。
3. **模型不能直接改状态。** 物理事实先抽取，再由代码生成 `FactBatch`。
4. **检查提交后的事实，不枚举行动前的能力。** 自然语言和行动提案走同一条管线。
5. **感知按主体隔离。** 不能把完整世界交给模型再靠 prompt 要求忽略。
6. **提交原子、可撤回。** 冲突候选零状态变化；成功才增加 revision 和 checkpoint。
7. **内容校验只守引用完整性。** 它不判断玩家该做什么、故事何时结束或人物应该答应什么。

## 当前不在核心的机制

- 承诺、披露、关系和情绪的结构化账本；
- flags / world / player / scene / character 动态状态；
- storylet、effect、条件出口和条件结局；
- Director、NPC 自动回合、Local Canon 和生成预算；
- world graph 寻路、意图、能力、报价和数值裁决。

分层记忆的 M1 保存分支内原始回合事件，M2 按窗口或字符预算生成滚动小结，M3 把小结和未压缩事件组合成主体与 revision 绑定的生成上下文。旁白与行动提案共享它，事实抽取不读取它。所有摘要仍是可观察、可重算的软上下文。硬机制只能在记忆仍不能可靠解决某类失真后，作为小型选装模块回归。
