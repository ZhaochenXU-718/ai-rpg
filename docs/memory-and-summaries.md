# AIRPG 记忆与小结

## 原则

叙事记忆用于帮助模型承接故事，不是权威世界状态。它可以保存对话、约定、人物态度、开放事项和场景意义，但不能直接修改人物位置或关键物品归属。

## M1：原始事件层

每次成功提交创建一个不可变 `MemoryEvent`：

- `turn_no` 与 `commit_id`；
- 玩家原话与已提交散文；
- 场景前后；
- 回合涉及的在场人物和显式引用；
- 实际提交的物理变化。

失败候选不会产生事件。完整事件列表留在当前 `MemoryState`，最近 4 个事件也继续保留在兼容的 `PerceptionSnapshot.recent_events` 中。

M1 只建立玩家叙事记忆。NPC 感知不会复用这份最近事件；独立的 NPC 亲历记忆留到后续批次。

`MemoryState` 包含以下软小结字段；M1 只预留，M2 开始按需填写：

- `rolling_summary`；
- `open_loops`；
- `character_notes`；
- `scene_notes`；
- `recently_resolved`；
- `compacted_through_turn`。

这些字段不会出现在 `state`，也不参与物理事实检查。

## 时间线语义

checkpoint 保存完整 `MemoryState`。撤回会恢复祖先记忆，从祖先继续行动时形成独立的新记忆序列；原分支事件仍保留在原 checkpoint。

原型阶段直接复制不可变快照，优先保证语义清楚。等出现真实的持久化或规模问题后，再考虑事件存储去重。

## 可观察入口

- `memory`：当前软记忆、小结和最近 4 个事件；
- `memory raw`：最近 10 个原始事件及物理变化；
- session log / trace：随成功提交记录完整 `MemoryEvent`。

所有玩家可见输出都标注“非权威状态”。

## M2：按需滚动小结

每次玩法回合先完成物理提交、事件追加和 checkpoint 创建，再检查是否需要压缩。小结因此是提交后的尽力而为步骤，不能阻止或回滚刚发生的回合。

当前阈值：

- 最近 4 个事件保持原文，不进入压缩批次；
- 更早的未压缩事件达到 4 个，或玩家原话与散文合计达到 2400 字符时触发；
- 若有模块仅因前置状态未判定而被 `requires` 卡住，允许绕过批量门槛提前触发一次（trigger 为 `module_bookkeeping`），保护窗与冷却不变；
- 一次最多压缩 6 个旧事件，模型只能处理引擎选择的边界；
- 无加速时，首次按事件数量触发通常发生在第 8 个已提交回合。

小结请求只包含旧小结、选中的已提交事件，以及压缩边界前玩家已经亲历过的人物/场景目录；远处作者实体不会为了提供 ID 而暴露给小结器。DeepSeek 使用非思考、低温、800 token 上限的 JSON 调用；坏 JSON、空响应或传输错误不在同一回合修复重试。

成功结果更新：

- `rolling_summary`；
- `open_loops`；
- `character_notes` 与 `scene_notes`；
- `recently_resolved`；
- `compacted_through_turn`。

人物与场景小结只能使用作者目录里的 ID，压缩边界由代码写入而不是由模型决定。结果附着到当前 checkpoint，不增加回合、checkpoint 或物理 `state_revision`。

失败时仍保留全部原始事件，只记录失败原因和尝试回合。接下来的 2 个回合跳过压缩，第 3 个新回合才允许再次尝试，避免持续调用失败服务。失败原因可在 `memory` 和 trace 中观察。

## M3：生成上下文

M3 在每次生成前从当前 `MemoryState` 派生 `MemoryContext`，不额外持久化一份副本。旁白和 `ideas` 使用同一结构：

- 当前玩家主体、回合号和 `state_revision`；
- 滚动小结及其 `compacted_through_turn`；
- 开放事项、人物/场景小结和最近解决事项；
- 压缩边界之后仍未进入小结的原始事件。

上下文与感知的主体、回合和 revision 必须一致，恢复 checkpoint 后生成的旧上下文不能跨到新分支使用。当前只建立玩家记忆；请求 NPC 上下文会得到空结果，不会复用玩家小结。

### 预算与空档处理

未压缩事件**逐字进入上下文**——它们是旁白与提案续写的直接上文，最近散文的结尾（提问、未决动作）就是"现场状态"，一个字都不能丢。事件侧预算 6000 字符、最多 8 条，超限时**从最旧一侧整条丢弃**（滚动小结本来就覆盖旧内容），绝不逐条裁剪；只有单条事件独自超过全部预算的病态情况才对该条保尾截断。小结与结构化笔记维持各自限长，摘要侧预算 2400 字符。`text_chars` 与 `truncated` 让降级结果可观察。

这里携带的是“压缩边界之后的事件”，不只是固定最近 4 条。正常情况下，首次小结生成前可能积累 5–7 个未压缩回合；把它们暂时放进上下文，可以避免为了减少小结调用而在第 5–7 回合制造记忆空档。小结成功后，这个缓冲自然缩回边界之后的 4 条近期事件。

### 权限与降级

- `MemoryContext` 只进入旁白和行动提案请求，不进入 `FactExtraction`；
- prompt 明确规定当前感知与物理事实优先，开放事项和人物笔记不能自动变成已经完成的事实；
- 记忆中的远处人物不会因此成为当前在场或可行动对象，提案结果仍经过现有可见实体过滤；
- 小结失败原因不会进入 prompt；原始事件仍可提供降级上下文；
- digest 结构损坏时先退回纯原始事件，再失败才完全省略记忆，不阻断生成；
- narration / suggestions trace 记录实际使用的裁剪后上下文。
